# Existing synthetic Demo dataset

This is the existing dataset, not a redesigned replacement. `scripts/demo/scenarios.ts` preserves the canonical input definitions byte-for-byte; `ASSET_MANIFEST.json` records the original source bytes.50 showcase projects P001–P050,10 workflow examples S01–S10,5 named university contexts, the original authors/team sizes,60 approved reviewer profiles, original metadata/native content and exact rubric inputs are retained. University names are context for fictional records, not endorsements or real institutional assessments.

The540 input files are50 showcase covers,10 existing workflow covers and480 existing native documents/code/data files. The workflow covers reuse their existing image bytes. Uploaded sample code remains data; the installer never executes those files or reruns the sample experiments. Existing synthetic results/reports are examples, not a new platform performance study or human evaluation.

The loader uses real onboarding, credential hashing/login, native storage/policy, lead submissions/packet consent, supervisor decisions, local SMTP/OTP, independently attributed committee forms and event-driven external review. It does not insert fabricated official grades, bypass eligibility, cap reviews at two, redesign the scheduler or weaken exact-70/score concealment. The original inputs produce100 reviews across the top ten; actual total completion counts and80 escalation transitions are verified, not assumed from a target field.

Workflow examples preserve draft, requested FINAL, quality screening, supervisor assessment, committee assessment, publication decision, assessed revision, retention, published independent-review and partial-committee states. Existing partner pending/approved/rejected/suspended, active/revoked/denied/pending exact-edition access and reserved/invited onboarding slots are retained.

Necessary per-install adaptations: use the installation's secure administrator instead of a private factory administrator; generate new passwords/IDs/timestamps/capabilities; use owned local storage/Mailpit; retain the unregistered student slot's synthetic.local address instead of a private operator-mailbox override. These do not replace projects, content, relationships or academic scenarios. Private host/checkpoint/reset/restore code, production dumps/originals, credentials and model caches are not included or invoked.

Choose `--demo` only on a new blank owned installation. A marker binds it to that instance/input manifest. Interrupted generation resumes through its journal while the app remains closed. A completed installation is a no-op on rerun, including after users edit its sample records; it never reseeds, deduplicates by destructive replacement, purges or overwrites their data. A nonblank installation without an existing owned Demo journal is refused before stopping its app.

Use `bash scripts/demo-accounts.sh` in a private interactive terminal to select a generated synthetic account. Credentials are private state with mode 0600, never shipped in this dataset. They describe initial Demo credentials; if a user changes a password, keep that change and use the normal account recovery workflow. The initial administrator uses the installer credential handoff. Account setup and guest OTP remain normal application flows; this is not an authentication bypass.

Detailed generation/semantic verification is installation evidence, not a claim that every source thesis scenario or human walkthrough was executed. Public source/usage permission still requires the exact release activation described in EVAL-1.
