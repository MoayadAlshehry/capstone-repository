# Security reporting

Capstone Repository is an academic capstone platform supplied for the local evaluation scope defined in [RIGHTS.md](RIGHTS.md) and the applicable release receipt. Its engineering checks and supported environment are documented in [TESTING.md](TESTING.md). These checks provide scoped verification evidence; they are not a formal security certification or a general production-suitability guarantee.

Keep credentials, private academic records, working exploit payloads and recovery information out of public issues. Where GitHub private vulnerability reporting is enabled, use **Security → Report a vulnerability**. Otherwise, request a confidential reporting channel from the maintainer without including sensitive details, and wait for that channel before sharing the report.

Identify the affected immutable release, relevant source paths and a minimal synthetic reproduction. Test only an instance you own and have permission to assess. Do not probe the demonstration site, other users' installations or third-party model/mail services. Do not include session cookies or token values in reports.

The maintainer can triage a supported report and propose a separately versioned correction. Existing immutable tags/assets will not be silently replaced. Operators remain responsible for their own host, model/provider configuration, authorized data and backups.
